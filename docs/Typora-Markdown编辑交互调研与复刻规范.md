# Typora Markdown 编辑交互调研与复刻规范

本文用于 QTypora 复刻 Typora 的 Markdown 编辑行为。范围按用户确认限定为 Markdown 编辑交互，覆盖逐字输入、即时转换、块内编辑、选区、删除、撤销、剪贴板、输入法和源码切换。

用户确认“三连符号后按 Tab 创建代码块”的观察来自 **Typora 0.11.18**。输入交互优先以这个版本的观察和本机代码为参考；新版官方文档补充功能目录，必须保留版本条件。具体主题、设置和逐键结果尚未完全固定，不能把各版本行为混成一个默认值。

随后用户明确决定“三个反引号 + Enter，那就按这个来走”。QTypora 的代码块创建触发键据此确定为 Enter，现已实现并通过定向验证；原 Tab 观察保留为历史待实测项。

调研日期为 2026 年 9 月 30 日。官方支持站最近列出的主版本为 1.14，见 [官方索引](https://support.typora.io/) 和 [1.14 更新说明](https://support.typora.io/What's-New-1.14/)。系统文件关联和安装器已按用户要求搁置，不在本轮范围内。

## 主要结论与证据边界

官方明确写的是三个 ASCII 反引号后按 Enter 创建代码块。0.11.18 的 Tab 处理链路没有找到专门创建围栏的分支，但这不能替代完整实测，也不能直接否定用户观察。准确字符、光标位置、输入设置和操作序列仍需对照。[代码块说明](https://support.typora.io/Code-Fences/)

本机 Typora 的 package.json 确认为 0.11.18。实际启动显示测试版过期，无法进入编辑器，所以本轮没有在真实 Typora 中完成按键实测。本地旧版代码只读检查能够支持处理路径分析，不能证明最终界面和撤销行为。

QTypora 已有即时预览、源码切换、部分格式命令和可编辑表格，现新增代码块 Enter 创建及正文直接编辑。代码块的完整配置、段落换行、自动配对、富文本粘贴等仍有差异。调研和本次代码块增量不能标成全部交互已实现或 1:1 验收完成。

| 证据类别 | 含义 | 使用边界 |
| --- | --- | --- |
| 官方说明 | 官方支持页及版本记录 | 只确认明确描述的功能、设置和键位 |
| 0.11.18 代码 | 本机安装文件的只读检查 | 确认旧版路径；不替代最终 UI 观察 |
| 用户观察 | 用户确认版本及操作现象 | 保留现象；未观察到的细节继续验证 |
| 用户要求 | 井号加空格才转换等明确约束 | QTypora 产品要求优先 |
| QTypora 代码 | 当前实现和测试 | 支持能力与缺口判断，不证明相同体验 |
| 待实测 | 缺少逐键结果的项目 | 不允许写成已确认规则或计入完成率 |

## 代码块的创建和编辑

### 先区分输入字符

| 字符 | Unicode | 与本次交互的关系 |
| --- | --- | --- |
| 反引号 ` | U+0060 | 官方围栏示例使用的字符 |
| 单引号 ' | U+0027 | 不同于反引号 |
| 左右单引号 ‘ ’ | U+2018、U+2019 | 用户消息中出现的弯引号，不同于反引号 |
| 波浪线 ~ | U+007E | 旧版围栏候选识别也接受此字符 |
| 中点 · | U+00B7 | 旧版候选识别代码还接受此字符，最终行为待测 |

逐字键入、输入法提交、粘贴和菜单创建可能走不同路径。自动配对也可能使屏幕出现的反引号数量不同于实际按键次数。复刻时必须记录真实文档字符，不能仅按外形归一化。

### 官方确认的代码块能力

| 项目 | 已确认行为 |
| --- | --- |
| 创建 | 三个反引号加 Enter，或使用菜单命令 |
| 语言 | 可在围栏后输入，也可用块右下角输入控件修改 |
| 全选 | 块内 Ctrl+A 可选择代码正文 |
| 复制 | Code Tools 可复制正文 |

### 0.11.18 的处理链路

本机文件 [frame.js](<C:/Program Files/Typora/resources/appsrc/window/frame.js>) 压缩在一行。下列位置为读取字符串后的近似字符偏移，用于再次定位；本文不复制应用源码。

| 路径 | 偏移 | 检查结果 |
| --- | ---: | --- |
| 围栏候选识别 | 854384 | 独立段落匹配至少三个反引号、波浪线或中点，可带语言；单引号和弯引号不在此规则中 |
| Enter | 479874 | 先刷新段落解析，再进行块拆分和新块创建 |

| 语言补全确认 | 128171 | 选择候选语言后可以走块创建路径 |
| 补全键盘 | 131169 | 有 Enter 确认及 Escape 取消；未找到 Tab 确认分支 |
| 代码正文键盘 | 94064 | 方向键在边界处可离开；单行块起点 Backspace 可退回段落 |
| 代码编辑器创建 | 95857 | 编辑器接收正文，语言、行号、换行、缩进单独配置 |

静态代码支持“候选文字、确认创建、正文编辑”分成不同阶段的判断。Tab 主分支及其插入、补全路径没有直接解释用户观察；是否存在其他状态变化或操作时序，需要实际运行同版本确认。这里保留这一证据冲突；当前 QTypora 的 Enter 实现依据用户后续决定，而非声称已证实旧版 Tab 观察。

0.11.18 内置 CodeMirror 的基本键表将 Shift+Tab 映射到 indentAuto；正文边界处理还包括无选区且位于末行末尾时 Ctrl+Enter 插入后续段落。两项来自旧版代码，需实测其有效键表及焦点条件。

### 新版代码块行为必须单独记录

1.5 起代码块和源码中的 Shift+Tab 默认减少缩进；配置后可以用于自动整理。代码块页的“indent”文字与更新记录冲突，应结合版本记录和实际菜单确认。[1.5 更新说明](https://support.typora.io/What's-New-1.5/)

1.6 起支持默认语言或 Last Used，可分别用于菜单创建、语法创建或两者；自动填入的语言可用 Backspace 或 Undo 移除。这是新版能力，不能默认套到 0.11.18。[1.6 更新说明](https://support.typora.io/What's-New-1.6/)

## 官方功能目录和 QTypora 差异

### 即时预览与段落

Typora 默认采用可编辑的即时预览，行内格式标记会随编辑位置显示。Windows 的 Ctrl+/ 切换全文源码。1.13 明确增加源码与即时编辑视图之间的滚动位置保持；这是新版记录，不直接说明 0.11.18 的位置策略。[Quick Start](https://support.typora.io/Quick-Start/)、[快捷键](https://support.typora.io/Shortcut-Keys/)、[1.13](https://support.typora.io/What's-New-1.13/)

| 项目 | 官方规则 | QTypora 差异或验证项 |
| --- | --- | --- |
| 普通段落 Enter | 新段落，源码两个换行 | 当前默认 Enter 没有普通段落双换行命令 |
| Shift+Enter | 段内单换行 | 与列表和块编辑分别验证 |
| 连续空白及单换行 | 编辑视图默认保留，打印导出另可配置 | 缺少独立解析设置 |
| 硬换行 | 尾随两个空格加换行或 br 标签 | 比较源码保持与展示 |

依据 [空白和换行](https://support.typora.io/Line-Break/)。普通段落规则不能机械用于标题、列表、表格、代码和公式内部。

### 表格

官方描述表头语法创建、Ctrl+Enter 插入下一行、Tab 增行、删行列、尺寸控件、列对齐及拖动重排。尺寸超过六列或十行可直接输入数字。[Table Editing](https://support.typora.io/Table-Editing/)

QTypora 的 `live-table.ts` 将 Tab 和 Enter 都处理为单元格扁平列表的前后移动；最后一格没有增行路径，Ctrl+Enter 也无独立分支。已有右键行列操作和对齐，缺尺寸控件、拖动和完整跨格选择。Tab 增行的准确边界仍要实测。

验收还需包含空表头、空正文行、转义竖线、格内格式、中文组合输入、多行多列粘贴、方向键越界、Shift 选区、局部和整表删除、撤销恢复原空白。Enter 的移动或换行规则不能凭习惯选择。

### 图片与 HTML

图片支持语法、文件选择、拖放及剪贴板输入；复制目录、路径写法和文档级目录设置影响最终源码。尺寸可以通过 img 属性或 style 调整。[Images](https://support.typora.io/Images/)、[Resize Images](https://support.typora.io/Resize-Image/)

QTypora 有文件导入、本地展示和部分右键操作，拖放、剪贴板、文档级路径设置和 HTML 尺寸尚未对齐。图片整体适配宽高已有测试，但与目标 Typora 主题的尺寸策略仍需比较。

HTML 要区分编辑与预览；脚本不执行，事件属性不支持，iframe 受沙箱约束。[HTML Support](https://support.typora.io/HTML/)

QTypora 采用标签白名单，视频、音频、iframe 等能力有缺口，图片尺寸和 style 也会被移除。补齐功能需要保留相应内容安全约束。

### 剪贴板与删除选择

复制可以同时写 HTML、RTF、纯文本；普通纯文本默认通常不含 Markdown 标记，可配置保留源码。即时编辑优先把 HTML 转 Markdown，源码模式选纯文本；Ctrl+Shift+C 复制 Markdown，Ctrl+Shift+V 粘贴纯文本。[Copy and Paste](https://support.typora.io/Copy-and-Paste/)

QTypora 的右键复制提供 text 和 HTML，普通 text 仍是选择的源码，无 RTF；普通与纯文本粘贴都读取文本。快捷键、原生菜单、右键和鼠标粘贴必须统一处理规则。

| 范围 | 官方描述 | QTypora 验证项 |
| --- | --- | --- |
| 样式或单元格 | Ctrl+E | 已有实现，嵌套范围待测 |
| 行句或表格行 | Ctrl+L | 通用与局部范围需对齐 |
| 单词 | Ctrl+D 选择，Ctrl+Shift+D 删除 | 检查默认命令是否抢占 |
| 语义删除 | 块、行句、样式、词有不同范围 | 缺完整命令及菜单 |
| 移动行段 | 1.11 扩展 Alt+上下键至列表及其他块 | 新版扩展，需比较范围和重编号 |

### 搜索与辅助状态

搜索提供大小写、整词、正则和捕获组替换。[Search](https://support.typora.io/Search/)

## 一比一验收方法

一致性包括 Markdown、渲染结构、光标选区、撤销重做、设置与模式。空白行、全选范围、撤销粒度不同，即使外观相似，也应记录为差异。

每项功能至少覆盖：

1. 空文档、文首、文中、文末、列表或引用嵌套。
2. 无选区、单行、多行、反向选区。
3. Enter、Shift+Enter、Tab、Shift+Tab、方向键、Backspace、Delete。
4. 逐字输入、粘贴、输入法、菜单与快捷键。
5. 功能默认、关闭、开启，源码与即时编辑。
6. 一次及连续撤销、重做、保存重开、视图切换。

## 已实现并验证的代码块输入

2026-09-30，用户确定采用三个 ASCII 反引号加 Enter。即时编辑模式中的行为为：

1. 独立行输入三个反引号时仍显示原字符；行末 Enter 补齐闭合围栏，光标进入空正文，不添加“代码”占位文字。
2. 支持围栏后显式语言、较长围栏和最多三个行首空格；已有正文、行内文本、引用或列表嵌套、形似引号不走此创建路径。源码模式继续使用普通 Enter。
3. 代码正文使用原生 CodeMirror 文本编辑，隐藏围栏，保持 Markdown 字面内容；右下角可修改语言。Mermaid 保留既有图表编辑路径。
4. 块内 Ctrl+A 选择正文；正文末尾 Ctrl+Enter 进入后续段落；空块起点 Backspace 退回段落。
5. 一次撤销恢复输入的围栏及原光标，重做恢复空正文光标；源码双向切换和保存保持原文。

定向模型及键盘测试共 3 文件、39 项通过；真实隔离 Electron 回归 7 项通过，覆盖创建、输入、语言修改、撤销重做、源码模式、空块删除、正文全选、退出、保存，以及既有标题、表格、链接/公式右键复制和模式切换。代码正文与语言栏连续显示已检查截图。合成 composition 状态有保护测试，实体输入法仍待真机验收。

实现及证据见 [live-code](../src/renderer/editor/live-code.ts)、[模型测试](../src/renderer/editor/live-code.test.ts)、[桌面测试](../tests/code-fence.spec.ts) 和 [验证记录](开发验证记录.md)。该结果确认本次用户规则，不代表已与可运行的 Typora 0.11.18 完成逐键或像素对照。

## 代码语言输入与补全增量

2026-09-30，用户要求语言范围超过 Python、JSON、HTML、Markdown，并确认创建时可直接写语言。

官方 [Code Fences](https://support.typora.io/Code-Fences/) 确认：三个 ASCII 反引号加 Enter 创建代码块；起始围栏后写语言名可指定高亮，也可在既有代码块右下角输入框修改语言。[Language Support](https://support.typora.io/Code-Fences-Language-Support/) 确认大小写不敏感、常用别名及 CodeMirror 高亮引擎。默认语言和 Last Used 属于 1.6 起新增配置，不能作为 0.11.18 基线。

本机安装的 0.11.18 静态代码 `C:/Program Files/Typora/resources/appsrc/window/frame.js` 中，语言候选和自动补全模块约在字符偏移 125600–132200：查询转小写并按前缀匹配，候选排序，约五行滚动视区，支持方向键、PageUp/PageDown、Home/End、Enter 选择及 Esc 关闭，鼠标按下避免输入框失焦。该结果是代码调查；本机旧版已过期，未做同版本 UI 实测。

QTypora 本次实现：

1. 接入既有 CodeMirror 6 的 143 项语言目录，输入框与 Markdown 代码解析共用同一解析映射，解析器按需加载。
2. 语言名称和别名按大小写无关的前缀补全；空查询展示完整候选。支持 `js`、`ts`、`cpp`、`bash`、`py`、`gfm`、`htmlmixed`、`mssql` 等别名。
3. 右下角候选支持键盘、鼠标选择；五行视区滚动，空间不足时向上展开，滚动或调整窗口时关闭。按 Esc 关闭候选，再按 Esc 恢复原语言。
4. 输入完整语言名后 Enter 或失焦应用；选择建议写入标准语言标识。已知多词名称转成单个标识；未知名称保留，按纯文本显示。清空语言也按纯文本显示。
5. 起始行写三个反引号后紧接 `Python`，或写空格加 `python`，再 Enter，直接进入带 Python 语言的代码块；空围栏默认不填语言。符号是英文反引号，不是中文引号。
6. 修改语言保持正文原文，每个块独立撤销重做；确认后回到代码正文，源码切换清理候选控件。

差异边界：143 项是当前依赖目录的数量，并非 Typora 官方语言名单的完全对应；例如官方列出的 ABAP、Nim、Elixir 当前目录没有对应解析器。未添加虚假候选或用其他语言的高亮冒充支持。旧版静态代码选择建议后保留语言输入焦点，本次沿用 QTypora 已有的确认后回到正文行为。默认语言配置、实体 IME、同版本焦点与像素对照仍待后续实现或验收。

实现见 [语言目录](../src/renderer/editor/code-languages.ts)、[候选控件](../src/renderer/editor/code-language-suggestions.ts)、[语言目录测试](../src/renderer/editor/code-languages.test.ts)、[桌面交互测试](../tests/code-fence.spec.ts)。本次覆盖语言选择和高亮，不计为全部 Markdown 编辑交互 1:1 完成。
