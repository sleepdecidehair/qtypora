# Typora 功能调研与 QTypora 差距核对

核对日期：2026-10-26。初始源码基线：`48e2db6`；本轮实现状态基于 `sp/typora-feature-parity` 工作区，测试结果见 [本轮验证记录](Typora-功能补齐验证-2026-10-26.md)。范围：Windows、macOS 本地 Markdown 工作流。

后续实现与当前剩余限制见 [2026-10-27 补齐记录](Typora-剩余功能补齐-2026-10-27.md)；下表保留本次核对时的状态。

## 结论和证据边界

QTypora 已有编辑器、文件管理、保存保护和基础导出的实现，后续重点是补齐兼容性和完整工作流。不能按已有按钮、第三方库或历史需求文档计算功能完成率。

本次重新读取官方稳定频道、支持站目录和相关专题，再核对实际源码、公共契约及桌面测试定义。官方稳定频道当前首项为 **1.14.15**，上次需求文档基线为 1.14.10；这里不推断补丁发布日期，也没有执行 Typora 1.14.15 实机对照。[稳定频道](https://typora.io/releases/stable)、[支持站目录](https://support.typora.io/)

本文件是当前差距核对；既有 [完整需求文档](Typora-Windows-完整需求文档.md) 保留详细需求编号与历史设计依据，其中“目前没有应用代码”等描述已经过时。[旧剩余工作清单](Windows-剩余工作与并行计划.md) 的状态也不能作为当前实现结论。

状态定义：

- **已有 / 已实现**：找到完整的基础调用链；不表示所有平台已经验证，也不表示与 Typora 像素或全部边界一致。
- **部分**：存在基础能力，但缺具体子功能、配置或交互。
- **缺失 / 未实现**：本次源码与入口核对未找到相应实现。
- **待验**：有实现或依赖基础，但证据不足以证明真实平台行为。
- **另立范围**：商业服务、实验能力、平台专用服务或外部生态，单独决策与验收。

下表按可交付能力分组，不把每个菜单标签重复当作独立功能；完整语法和命令仍按既有 PRD 对应章节展开。优先级表示补齐次序，不表示取消低优先级需求。官方证据按末尾 S 编号引用；源码文件名以本轮实现为准，历史行号仅作初始调研线索。

## 初始调研建议（保留历史依据）

以下方案与首批设计形成于实现前；用户随后授权多 Agent 并行补齐。本轮实际状态以上表及验证记录为准，不再把这份设计文字当作未执行结论。

方案 A（推荐）：按依赖分批补齐，每批完成源码保护和桌面验收。先统一语法/标题索引，再做图片剪贴板、表格、搜索与写作辅助、导出主题，最后平台服务与外部扩展。优势是每批能独立使用并复核，代价是完整对齐需要多个批次。

方案 B：按界面模块集中补齐，先做设置、菜单和面板，再接功能。界面进度较快，但容易留下无法工作的入口，不建议作为默认实现次序。

方案 C：一次覆盖全部差距。会同时变更编辑模型、资源权限、导出工具和平台集成，故障定位与回归风险最高，不建议单批交付。

### 首批建议设计：Markdown 兼容层

目标是同一份原文在实时预览、源码、大纲和 HTML/PDF 导出中有一致的语法解释。此处保留实现前设计；实际完成度见 E/R/W/X 对照表。

1. **YAML**：仅将文件开头已闭合的 `---` 块识别为前置信息，保留准确原文范围及编辑入口；不把元数据当标题。首批提供结构展示和原文编辑；导出使用经过类型检查的 title/author/description 等元数据。图片路径覆盖、导出配置覆盖和自定义程序字段留在各自后续批次，不由文档自行执行。
2. **目录与锚点**：建立统一标题索引，为标题分配稳定且去重的锚点；识别独占一行的 `[toc]`/`[TOC]`，随标题增删改更新。正文点击定位与导出 ID 使用同一索引。代码、公式、YAML 内的伪标题不入目录；重复标题、中文、标点、Setext 标题都纳入样例。具体 slug 规则作为 QTypora 明示规则，精确 Typora 兼容需同版本实测。跨文件打开后 fragment 定位单独补齐，不宣称首批完成所有链接行为。
3. **Alerts**：支持 NOTE/TIP/IMPORTANT/WARNING/CAUTION，保留引用语法、内联格式和准确源码范围；提供浅深主题样式与可访问的文字标签。未知类型保留普通引用，代码中的标记不转换。
4. **Markdown 设置**：为新增能力及现有高亮/上下标/行内数学/Emoji 等提供可持久化开关；旧设置缺字段时保留既有扩展的启用状态，新功能使用明确默认值（建议 YAML/TOC 开启、Alerts 关闭）。模式切换和设置变化不改变 Markdown 原文及撤销历史。严格模式、智能标点不混入本批。

组件边界：解析配置与标题索引作为可测试的独立模块；编辑器装饰、侧栏和导出共同消费结果，避免各自重新解释 YAML、目录和标题。主进程仅负责验证/持久化新增偏好及既有导出能力，渲染进程继续只调用固定 `window.desktop` 桥接。若需新增解析依赖，应在后续设计中明确版本、许可证及锁文件变化，不手写不完整 YAML 解析器冒充通用 YAML 支持。

实现预计涉及 `shared/contracts.ts`、主进程偏好验证、renderer 解析、实时块/行内装饰、偏好界面、样式、大纲及导出调用；按项目流程在独立 Git worktree 内开发。保留当前工作区的 `.gitignore` 修改和未跟踪 `.DS_Store`，不替用户提交、删除或 stash。

首批验收：

- 单元测试覆盖代码围栏/公式/YAML 排除、未闭合 YAML、重复标题、中文锚点、五类 Alerts、设置迁移及禁用退化。
- 真实 Electron 中检查目录点击后的可见坐标与目标标题、局部源码编辑、跨模式选区及滚动、撤销/重做；保存文件逐字比较未编辑范围。
- 修改标题后目录更新；HTML 导出 ID/目录一致，PDF 可生成；错误或缺失资源仍不能报告成功或覆盖已有输出。
- 保留 BOM、CRLF、混合换行未修改保存、只读文档、草稿和取消保存行为；复用既有桌面帮助器隔离用户目录。
- 运行类型检查、相关单元测试、编译及对应桌面测试；Windows 实体输入法和双方平台实机差异单列待验。

后续批次依赖：图片接收和资源策略（R01–R05、R12）→ 表格与大纲/搜索/统计（E16–E17、W09–W15）→ 导出/Pandoc/主题（X01–X10）→ 学术长尾、平台服务及外部扩展。每批仍按表中条目核销，不能因首批完成而把其余差距标为完成。
