# Typora 右键菜单调研与 QTypora 实现要求

日期：2026-09-30。目标平台：Windows 桌面；实现保留 Electron 跨平台接口。
范围：当前官方文档确认的功能、QTypora 本轮可执行的菜单、原文与文件保护、验收要求。

## 事实依据与版本边界

默认编辑模型为实时预览编辑，Ctrl+/ 切换全篇源码，Ctrl+E 选择样式范围或表格单元格。右键菜单根据点击对象变化，不另设“阅读模式”作为操作前提。[官方快捷键](https://support.typora.io/Shortcut-Keys/)、[快速开始](https://support.typora.io/Quick-Start/)

官方帮助确认了下表的操作能力；帮助网页未完整公布每个版本、语言及操作系统的菜单顺序。本机已有 Typora 资源版本为 0.11.18，不能用来宣称已经逐项验收 Typora 1.14 的菜单文字、顺序和像素效果。QTypora 本轮采用中文 Windows 原生菜单，按对象组织已落地功能，精确同版本菜单对照仍列为后续工作。

| 点击对象 | 官方确认的能力 | 主要来源 |
| --- | --- | --- |
| 正文与选区 | 常规编辑、格式、复制 Markdown、HTML、带格式文本与纯文本的策略 | [复制粘贴](https://support.typora.io/Copy-and-Paste/)、[1.3 发行说明](https://support.typora.io/What's-New-1.3/) |
| 表格单元格 | 行列插入/删除、表格复制；保留表头、至少一行正文和一列 | [表格编辑](https://support.typora.io/Table-Editing/)、[Markdown 参考](https://support.typora.io/Markdown-Reference/) |
| 代码块 | 复制代码内容、自动缩进；代码工具与语言选择是相关功能 | [代码块](https://support.typora.io/Code-Fences/) |
| 链接 | 打开链接、复制链接地址 | [0.11 发行说明](https://support.typora.io/What's-New-0.11/) |
| 本地图片 | 复制、移动图片并调整引用；移动也用于重命名；删除图片原文件与引用 | [图片](https://support.typora.io/Images/)、[1.4 发行说明](https://support.typora.io/What's-New-1.4/) |
| 数学与图表 | 保存资源；部分对象可导出 SVG、PNG、JPEG；数学有额外复制功能 | [1.3 发行说明](https://support.typora.io/What's-New-1.3/)、[数学](https://support.typora.io/Math/) |
| 文件与文件夹 | 打开、新窗口、新建、副本、重命名、回收站、复制路径、资源管理器显示；文件操作撤销存在平台限制 | [文件管理](https://support.typora.io/File-Management/) |

“移除 Markdown 图片引用”与“删除原图片文件”是不同操作。普通文本删除不得隐式删除磁盘图片。[官方图片说明](https://support.typora.io/Images/)

## QTypora 的操作规格

### 原生菜单与目标绑定

- 用 Electron `Menu.popup` 展示原生菜单，renderer 仅提交对象类别及真正支持的动作集合，main 依据固定白名单构造菜单。[Electron Menu](https://www.electronjs.org/docs/latest/api/menu)
- 每个窗口最多一个待决菜单；替换菜单、取消、关闭窗口均结束原 IPC，取消返回空结果。
- 请求捕获文档 ID、正文范围、范围原文、选区及资源地址；返回后校验仍是原文档、原范围。文件菜单捕获工作区与路径，不能因活动文章或目录变化而作用于另一项。
- 右键选择树中的目标不激活文章；取消不改变编辑模式、正文、原有选区或编辑器焦点。
- 撤销/重做无历史时不出现；复制和剪切依赖有效选区；只读文档不提供正文修改或原图片移动/删除。
- 未命名文档没有磁盘操作菜单。目录不提供文档副本；工作区根目录不提供重命名或回收站。工作区外打开的文章只提供服务确实允许的打开、新窗口、路径复制和定位。
- 不展示未实现的上传、Word 复制、文件操作撤销或其它空入口。

### 正文及源码

常规动作：撤销、重做、剪切、复制、粘贴、全选；选区支持复制为 Markdown、HTML、纯文本，支持粘贴为纯文本。格式动作复用已有源码事务：粗体、斜体、删除线、行内代码、清除格式、六级标题、段落、引用、列表、代码、数学、表格、分隔线、链接和插入图片。

以 Markdown 原文作为唯一编辑源。格式命令、表格工具和资源引用修改都通过范围补丁执行，必须能撤销；不把渲染后的 HTML 整篇反序列化回 Markdown，避免改写其它段落的空白、引用式链接或原有写法。

本轮剪贴板实现文本与 HTML MIME 数据，不宣称已完成 RTF、外部富文本到 Markdown 的智能粘贴、主题复制偏好或全部 Office 互操作。[Electron Clipboard](https://www.electronjs.org/docs/latest/api/clipboard)

### 表格

菜单根据被点击的单元格定位行列，提供上/下插行、左/右插列、删除行列、左/中/右对齐、复制表格和删除整表。

- 表头不得通过“删除行”删除；唯一正文行、最后一列不得通过局部删除消失。
- 删整表使用独立动作。插入、删除、对齐只修改对应表格范围，表格前后正文逐字保持。
- 对齐修改 Markdown 分隔行；不靠展示样式假装原文已保存。
- 菜单 availability 和底层表格操作都检查最小尺寸，避免绕过界面限制。
- 转义竖线、首尾竖线可选、原有间距、多行表格和连续撤销需要样例验证。

拖动行列排序、尺寸选择器、跨单元格选区及表格高级浮动工具栏不计入本轮完成范围。

### 代码、链接、数学及图表

- 代码：复制块内代码，不带围栏；自动缩进与源码编辑必须实际落到原文。
- 链接：复制地址保留语义地址，打开复用 main 的协议许可；`javascript:` 等执行性地址不打开。
- 数学：复制 TeX 源码及实际 MathML，显示编辑入口。没有验证 Windows Office 专用剪贴板协议之前，不能命名为“复制为 MS Word”。
- 图表：复制 Mermaid 源码、明确编辑入口；支持已渲染资源的 SVG、PNG、JPEG 保存。
- 数学/图表导出从渲染结果生成独立资源，不把编辑器当前缩小后的 CSS 尺寸当成原图尺寸。SVG 保留有效颜色、字形、内部资源引用，拒绝外部 URI、脚本、事件和执行性元素；位图控制尺寸和像素预算。
- 文档或块改变后，迟到菜单不修改新内容。渲染失败的对象不显示假导出入口。

### 图片文件

| 动作 | 磁盘行为 | Markdown 行为 |
| --- | --- | --- |
| 复制地址 | 无 | 无 |
| 复制图片到… | 创建实际副本，目标不得覆盖已有文件 | 替换当前图片地址为副本地址 |
| 移动/重命名图片… | 写入新目标后移除旧文件；用户选择真实目标并确认共享引用影响 | 替换当前图片地址 |
| 图片另存为… | 保存原文件副本 | 保持引用 |
| 移除图片引用 | 不修改图片文件 | 仅移除当前图片 Markdown |
| 删除图片（原文件及引用）… | 确认后移至系统回收站 | 删除当前引用 |

操作仅接受当前文档真实引用、已授权且属于普通本地文件的图片。远程图片不提供本地移动/删除。相对路径结合实际文章路径解析；目标地址按文章位置生成，必要时使用 `file:` 地址。

图片请求包含正文和 revision。打开原生对话框前同步快照；真正移动/删除前再次检查文档版本、引用和源图片哈希。正文改变、文章关闭、图片被外部修改或目标已存在时结束操作，保留原文件。取消不修改原图或正文。

文件操作与 Markdown 撤销历史是不同层次；文本撤销不能自动恢复已移走的原文件，本轮依赖明确确认和系统回收站，不宣称已有完整文件撤销。

### 文件与目录

菜单提供打开、在新窗口打开、在目标目录新建文件/目录、创建副本、重命名、回收站、复制路径、资源管理器显示及刷新。目录新窗口启动时加载真正工作区及目录条目。

“创建副本”复制磁盘版本，保留原文档未保存草稿，不擅自保存或激活副本。重命名同步所有窗口中打开文章的路径元数据并保留脏正文。新建/重命名对话框提交时再次校验工作区、目标与重复提交状态。

## 图片与图表完整展示要求

根据用户最新明确要求：**任何图片或图表默认必须一次展示完整，即使缩小也可以。**

- 同时限制正文可用宽度和编辑器可见高度，等比 contain，缩放系数 `min(1, availableWidth/naturalWidth, availableHeight/naturalHeight)`。
- 默认不裁切、不放大、小图保持自然尺寸；不依赖横向滚动才能看全。
- 普通图片按自然尺寸；Mermaid 按 SVG viewBox；宽大数学式按实际排版尺寸缩放。
- 覆盖 Mermaid 自带的像素 `max-width`，防止其行内样式破坏适配。
- 异步图片/图表完成、窗口缩放、正文宽度改变后重新计算，并通知编辑器测量新高度。
- 这里的“一次完整展示”指每张资源可完整落在一个正文视口中；不要求整篇所有资源同时铺在同一个屏幕。
- 资源源码与文件不因视觉缩小而改写；查看资源和原尺寸导出是额外能力，不代替默认完整展示。

### 局部查看（2026-09-30 增量）

用户补充要求：全图缩小后文字难以阅读，应优先提供局部放大能力。
这项功能作为 QTypora 的查看器增强实现，不将其描述为已确认的 Typora 原生功能。

- 普通图片右键“查看原图片”，Mermaid 与数学资源右键“查看资源”打开覆盖窗口；初始完整适配，小图不自动放大。
- 滚轮放大或缩小鼠标指向的位置；左键拖动查看细节，限制边界，资源小于视口的方向居中。
- 工具条提供缩小、倍率、放大、适应窗口、原始大小和关闭。倍率以资源自然尺寸计，100% 是原始大小，最高 800%。
- `+` / `−` 缩放，`0` 适应窗口，`1` 原始大小，方向键平移，Shift 加大平移步长，Esc 关闭；Tab/Shift+Tab 在查看器内循环。
- 改变窗口大小时，全图视图重新适配；已放大视图保持倍率并尽量保留中心细节。重新打开时恢复全图。
- 查看器打开期间隔离正文快捷键，包括通过 Electron 原生菜单到达的编辑命令；原生窗口关闭仍遵守草稿保护。
- 加载失败显示明确提示并禁用缩放。关闭后恢复编辑焦点，文章滚动位置、源码、历史和原文件不因查看而改变。

## 验收与剩余差距

模块验收包括目标判断、表格精确补丁、最小尺寸、原生菜单白名单/只读策略、取消与关闭、图片源/目标冲突、资源净化和窗口目录启动。桌面验收经过真实 renderer → preload → main → Electron MenuItem → 返回动作链路，测试只替换原生弹窗的选择，不建立假 DOM 菜单。

需确认：不同文章右键取消保留草稿和焦点、待决菜单跨工作区失效、副本不保存原草稿、目录新窗口实际加载条目、局部表格工具可撤销、资源三种格式是可读取文件、图片取消和迟到正文更改保护磁盘，以及普通大图/图表在窗口缩小后仍完整显示。

当前明确差异：数学仅提供 TeX/MathML 复制与查看，不提供数学 SVG/PNG/JPEG/Word；引用式 `![alt][id]` / `[text][id]` 的定义 URL 尚未映射右键目标，落普通正文菜单；含图片、公式的富剪贴板兼容尚缺。

后续仍有：同版本所有菜单排列/文字对照、Office/RTF 互操作、图片上传/拖放/剪贴板与尺寸偏好、文件操作撤销、图表引擎长尾与数学高级工具。完成本轮基础上下文操作不等于完整 Typora PRD 已经实现。
