## 1. 问题描述

代码正文与语言栏之间出现空行。代码块之后右键点击链接，复制链接地址没有执行，剪贴板仍为刚复制的代码。失败位置：[context-menu.spec.ts](../../tests/context-menu.spec.ts:217)。

预期复制 `https://example.com/context`，实际仍为 `const value = 1;` 与 `console.log(value);` 两行代码。新增代码块三项桌面用例最初通过，扩展到既有链接与公式右键用例后发现问题。

## 2. 根本原因分析

1. 在隔离 Electron 中单独复现，排除并行测试恢复剪贴板这一假设。
2. 比较同一链接的 `view.posAtDOM(element, 0)` 与中心坐标的 `view.posAtCoords`：前者为正文偏移 55，后者错误返回链接之后的空行偏移 88；右键菜单实际缺少 copy-link。
3. 检查 contentDOM，围栏的 `inclusive: false` 块替换两侧生成多余 `.cm-line`，解释可见间隙。
4. 比较 DOM 和 `viewportLineBlocks`：语言栏高度 40px，另有 16px 的 margin-bottom；高度图没有包含该外边距，之后所有行的坐标计算偏移。
5. 去除外边距并修正块替换边界后，坐标返回链接内部偏移 56，实际菜单恢复 open-link/copy-link。

直接原因分别为块替换端点保留了额外文本行，以及组件外边距没有计入 CodeMirror 高度图。根本原因是用普通 DOM 布局习惯设计编辑器块组件，未同时校验其原生高度和坐标模型。最初只测代码内容保存，缺少块布局与相邻对象定位回归。

## 3. 解决方案

开围栏替换设置 `inclusiveStart: true, inclusiveEnd: false`，消除围栏前的空行，同时保留正文首行的 line 装饰和语法高亮；闭围栏使用默认块替换边界。语言栏使用自身 padding，不再使用外部 margin。

位置：[装饰构造](../../src/renderer/editor/live-code.ts:133)、[样式](../../src/renderer/editor/editor.css:96)。保留现有右键坐标算法，避免以链接特例掩盖整个高度图偏移。

## 4. 验证与预防措施

- 新增真实布局断言：末行正文底部与语言栏顶部误差小于 1px，见 [code-fence.spec.ts](../../tests/code-fence.spec.ts:43)。
- 既有代码、链接、公式原生右键复制用例已通过；相关桌面回归 7/7 通过。
- 查看最终截图，正文与语言栏背景连续，围栏不可见，后续段落正常显示。
- 后续块组件使用内部尺寸保持高度可测；新增影响正文布局的装饰时，验证后续文本点击及对象右键位置，不能只验证当前块。

## 5. 经验总结

编辑器块布局必须与编辑器测量模型一致；可见间距变化也可能改变后续文本的鼠标定位。
