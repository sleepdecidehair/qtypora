## 1. 问题描述

空文档输入三个反引号、Enter 创建空代码块，再撤销及重做。文档正确恢复为八个字符的完整围栏，但光标在偏移 8，应该在空正文偏移 4。

失败断言：`expected 8 to be 4`。直接检查 EditorState 而非只观察 DOM，排除了显示装饰造成的视觉误差。回归位置：[live-code.test.ts](../../src/renderer/editor/live-code.test.ts:44)。

## 2. 根本原因分析

1. 初次创建事务已设置偏移 4，因此不是创建时定位错误。
2. 撤销恢复围栏及偏移 3，只有重做发生偏移，范围缩小到历史记录恢复逻辑。
3. 检查本机 `@codemirror/commands/dist/index.js:353` 的 HistEvent 及 `:527` 的 pop：历史保存修改前选区，修改后的选区由后续选区事件记录；缺少该事件时，从原选区映射到修改后文档。
4. 开发候选只在文本事务中设置正文光标，未补充后续选区事件。旧偏移 3 正向跨过整段插入文本，重做时得到偏移 8。

直接原因是历史没有保存正文位置作为修改后的选区。开发时错误地认为单次事务中的 selection 会自动成为重做的目标选区；最初只检查创建结果，未立即覆盖完整撤销重做序列。

## 3. 解决方案

在创建事务后追加同一正文选区的 `select.code` 事务。该事务没有文本修改，记录修改后的光标，又不增加文本撤销步骤。创建使用 `isolateHistory.of('full')`，与此前输入保持边界。

位置：[confirmCodeFence](../../src/renderer/editor/live-code.ts:57)。

```ts
view.dispatch(transaction)
view.dispatch({ selection: view.state.selection, userEvent: 'select.code' })
```

无需临时绕过，也不修改 CodeMirror 内部历史实现。源码模式不安装本次创建命令。

## 4. 验证与预防措施

- 已断言创建后正文光标、一次撤销的原文和光标、重做的原文和正文光标。
- 已通过真实 Electron 的创建、撤销、重做后继续输入，确认未把正文输入到闭合围栏之后。
- 后续新增自动配对或块转换命令，必须把文档和选区同时纳入撤销重做验收，不能只看最终文本。

## 5. 经验总结

文本事务设置了光标，并不等于历史已经记录正确的重做光标；需要验证历史机制实际保存的前后选区。
