## 1. 问题描述

用户点击“引用”后，再次点击不能恢复普通段落。对 `正文 **格式**` 连续执行两次引用命令，修改前两次结果均为 `> 正文 **格式**`，没有运行时异常。

另一个边界是文档首行为空：对 `\n后续内容` 的位置 0 执行引用，旧行范围计算返回 `{ from: 1, to: 0 }`，形成无效替换范围。

## 2. 根因分析

1. 工具栏和快捷键均通过 `src/renderer/editor/MarkdownEditor.tsx:47` 调用 `createTextEdit`，因此先直接复现该命令，不依赖鼠标焦点或预览样式。
2. 旧引用分支调用通用 `lines(..., '> ')`：通用行格式转换先删除已有结构标记，再无条件添加 `> `，第二次执行只是重新应用引用。
3. 同一转换还会删除标题、列表标记，不能保证“添加引用—取消引用”恢复原有内容结构。
4. 根本原因是将引用当作单向格式转换，遗漏了取消分支及内容结构保留。已有测试检查了加粗切换、标题替换和列表边界，没有覆盖引用的第二次操作。
5. 首行边界来自 `lastIndexOf('\n', from - 1)`：位置为 0 时传入 -1，仍可能匹配位于索引 0 的换行。`src/renderer/editor/commands.ts:24` 现明确将文档起点设为 0。

## 3. 解决方案

- `src/renderer/editor/commands.ts:23` 提取共用行范围计算，保留选区末尾换行不包含下一行的规则。
- `src/renderer/editor/commands.ts:40` 新增引用切换：所选非空行均为引用时，删除一层引用标记；否则给普通行添加标记，已有引用行保持原有层级。
- 保留标题、列表、行内格式和缩进。支持空段落、引用中的空行、无空格引用标记及嵌套引用。
- `src/renderer/editor/commands.ts:79` 将引用命令接入专用切换函数。沿用已有编辑事务和撤销历史。

这是根本修复，无临时绕过方案；不扩展其他列表或标题按钮的切换行为。

## 4. 验证与影响范围

- 类型检查、构建通过；26 个测试文件中的 191 项单元测试通过。
- `src/renderer/editor/commands.test.ts` 补充 7 项引用回归，验证连续点击恢复、非选中内容不变、多行边界、混合选择、嵌套层级、空行和空首行。
- `tests/quote-toggle.spec.ts:20` 的两项真实 Electron 测试通过，分别覆盖源码和实时预览：按钮应用/取消、多行选择、取消空行引用后继续输入、保存、快捷键、撤销/重做和空首行。
- 当前用户窗口的最新热更新模块已验证：第一次命令生成 `> 正文`，第二次恢复 `正文`。验证只调用独立示例字符串上的纯函数，未对用户文档执行编辑操作。

- [x] 验证引用操作保留标题、列表和行内 Markdown。

## 6. 经验总结

引用是包裹内容的结构。取消时应移除引用层级，并保留内容自身的格式；命令复现与桌面交互验证需要同时覆盖第二次操作。
