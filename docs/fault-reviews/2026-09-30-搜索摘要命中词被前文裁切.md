# 故障复盘：搜索摘要命中词被前文裁切

## 基本信息

| 字段 | 内容 |

| 日期 | 2026-09-30 |
| 严重程度 | P3，开发验收阶段的显示问题 |
| 影响范围 | 新增目录搜索的长结果摘要，文件内容未受影响 |
| Issue / 提交 | 无；工作区增量开发，未创建提交 |

## 1. 问题描述

在窄侧栏查找 `002`，命中行包含 100 次重复的“长前文”。初版摘要已截去部分前文并生成 `<mark>`，但标记仍落在摘要可见宽度以外。桌面用例判断标记的左右边界是否位于 `<small>` 内，得到 `Expected: true / Received: false`。

## 2. 根因分析

`src/renderer/components/SearchHighlight.tsx:14` 初版保留命中之前的 24 个 UTF-16 单元。侧栏摘要使用固定可用宽度、单行及省略号；汉字比同数量英文字母占用更多宽度，保留的前文仍可能将关键词挤到裁切区。因此“DOM 里存在标记”不能证明用户能看到关键词。初版单元测试验证了分段字符串，真实桌面几何检查才发现这个问题。

## 3. 解决方案

把前文缩到 12 个 UTF-16 单元，保留省略号与命中之后的文本；截断点若落在 emoji 的代理对中间，退回完整字符边界。继续保留桌面用例的真实几何断言，未改为仅验证 `<mark>` 存在。

对应位置为 `SearchHighlight.tsx:14`、`SearchHighlight.test.ts:20`，以及 `tests/folder-search.spec.ts:112`。

## 4. 验证与预防

- 相关单元测试覆盖长中文前文、emoji 截断、大小写和字面量查询。
- 桌面用例确认命中词位于摘要可见宽度内，并验证点击后的正文高亮与原文保持。
- 已查看 `.debug/folder-search-highlight.png`，摘要和正文命中均清晰可见。
- 对带省略号的结果组件，同时检查匹配文字存在和实际可见范围。

## 5. 经验

搜索摘要的验收需要检查命中词的位置，不能只检查高亮节点是否生成。
