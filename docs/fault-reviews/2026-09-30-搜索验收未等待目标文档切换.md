# 故障复盘：搜索编辑验收未等待目标文档切换

## 基本信息

| 字段 | 内容 |

## 1. 问题描述

点击 `second.md` 的搜索结果后，用例等待正文出现两处 `002`，接着输入第三处。一次运行只得到两处，断言 `['002', '002', '002']` 超时，而其他轮次通过。

## 2. 证据与根因

前一篇文档也恰好有两处 `002`。只检查高亮数量，会在异步文件打开结束前通过。失败 trace 中，点击后约 24ms 就开始验证，验证约 2ms 后通过并紧接着发送键盘输入。

在隔离 Electron 窗口中把 `second.md` 的打开 IPC 延迟 250ms，复现相同过程：

```text
点击后：file = long.md，focus = BUTTON，matches = [002, 002]
打开完成后：file = second.md，focus = DIV，第二篇内容仍为原文
```

输入发生时焦点仍位于搜索结果按钮，并未进入第二篇正文。因此问题是测试把“匹配数量相同”误当成“目标文档已完成切换”，并非正文编辑后高亮漏更新。

## 3. 解决方案

`tests/folder-search.spec.ts:126` 在输入之前依次确认目标文件名、该文档原文、目标行的当前高亮及正文焦点。保留输入后的三处高亮断言，不增加固定等待，也不改应用的打开文件行为。

## 4. 验证与预防

最终相关 5 项桌面用例全部通过，覆盖跨文件切换、编辑更新、原文保留和原有标题展开。跨文件操作的验收必须等待文档身份和目标正文状态，不能使用多个文档可能共享的数量作为完成信号。
