# 故障复盘：未修改文档保存改变混合换行

## 基本信息

2026-09-30；P1 数据保真问题；发现于 PRD SAF-09 核对；工作区未提交 Git。

## 问题与证据

原实现打开时将 CRLF/LF 统一为编辑器 LF 文本，保存时总是按检测到的单一换行策略序列化。含 `# 标题\r\n\r\n中文内容😀\n末尾\r\n` 的原文，即使没有任何编辑也会被重新编码为全 CRLF。含编码 BOM 后另一个正文 U+FEFF 的文件，默认 TextDecoder 又移除了一次 BOM，导致正文字符消失。

代码链路：`src/main/files.ts:30` 的 `readMarkdown` → normalized buffer → `src/main/files.ts:79` 的 `saveMarkdown` → `encodedDocument`。最初只测试统一 LF/CRLF 和普通 BOM，缺少混合换行及编码头后仍有 U+FEFF 的边界。

## 解决方案

TextDecoder 显式 `ignoreBOM:true`，由文件层只移除一次已检测到的编码 BOM。版本 hash 核对通过且内容没有变化时，保存直接保留已验证的原始磁盘字节，不从规范化编辑缓冲区重建文件。

这不改变已修改文档按 LF/CRLF 设置输出的策略，也不把混合换行逐行编辑兼容计为全部完成。

## 验证与预防

`src/main/files.test.ts` 新增原始 Buffer 全等比较：中文 emoji、混合 CRLF/LF、BOM 和正文 U+FEFF 均覆盖。相关文件服务测试通过。新增或升级序列化逻辑时，必须区分“内容没有修改”与“明确重写”，不能只断言解析后的文字相同。
