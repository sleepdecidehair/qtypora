## 1. 问题描述

正文从固定 800px 改为适应窗口后，独立图片和表格缺少统一的居中规则。用户反馈表格靠左、图表与表格视觉错位，截图为 `C:/Users/Administrator/Desktop/ScreenShot_2026-09-30_212425_876.png`。

修改前实际窗口的正文中心位于 966px；一个宽度约 961px 的表格从 272px 开始，中心约 752.55px，相差约 213.45px。SVG 整体的中心位于约 966px，说明各类内容的水平布局不同。

## 2. 根因分析

1. 正文加宽消除了左右大片留白，但没有建立各类资源一致的水平布局。
2. `src/renderer/editor/editor.css:58` 原先设置表格水平外边距为 0，导致窄表格靠左。
3. 独立图片没有居中规则；图表依赖父容器的文字对齐，缺少自身的块布局约束。
4. 前一轮主要验证了宽度、完整显示、语法展开与原文保存，没有比较资源的实际中心位置。

## 3. 解决方案

- 表格保留自身宽度，水平外边距改为 `auto`。
- `src/renderer/editor/markdown.ts:79` 根据 Markdown token 标记仅由图片构成的段落为 `md-image-paragraph`，居中规则只针对独立图片段落。段落中的行内图片继续跟随文字。
- Mermaid SVG 使用块布局和自动水平外边距，保持比例、完整显示和原有内部图形布局。
- HTML/PDF 导出采用相同的图片段落、表格和 SVG 居中规则。

## 4. 验证与影响范围

- 类型检查、构建通过，184 项单元测试通过。
- 6 项桌面回归通过，涵盖独立图片、图表、表格编辑、双击源码展开、布局切换以及 HTML/PDF 导出。
- 隔离 Electron 窗口宽度为 1600px 和 760px 时，独立图片、表格和图表与正文中心的偏差均为 0px；行内图片保持 `inline-flex` 布局。
- 用户窗口中的表格、SVG 与正文中心偏差小于 0.01px；核对窗口操作前后的完整 Markdown，原文没有变化。

## 5. 预防措施

- [x] 图片段落识别同时验证独立图片、多个图片、文字中的图片和普通段落。
- [x] 资源布局检查比较实际边界和中心位置，并覆盖宽、窄窗口。
- 未来调整正文宽度时，同时检查图片、表格、图表和行内资源；图表应按整张 SVG 检查，局部节点的布局由图表本身决定。

## 6. 经验总结

修改正文宽度时，应一起验证每类资源的布局规则和实际几何位置。
