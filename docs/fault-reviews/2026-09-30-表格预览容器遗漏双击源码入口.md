| 日期 | 2026-09-30 |
| 发现人 | Codex，真实 Electron 回归测试 |
| 严重程度 | P2，一般 |
| 影响范围 | 本轮新增的表格双击源码入口；单击编辑单元格不受影响 |

## 1. 问题描述

用户要求双击预览内容显示 Markdown 语法。本轮实现后，图片、公式、图表成功展开，双击表格单元格仍保持渲染状态。

`tests/layout-and-editing.spec.ts:113` 首次回归报错：`expect(locator('.cm-live-edit-line').first()).toBeVisible()` 超时，元素不存在。测试当时的 DOM 快照仍包含渲染表格。

## 2. 根因分析

1. 同一次回归中，图片、公式、图表依次通过，失败发生在表格，排除统一编辑状态无法生效的假设。
2. 检查 `src/renderer/editor/live-table.ts:135`：表格使用 `.cm-live-table`，没有 `.cm-live-block`。
3. 新入口只匹配 `.cm-live-block,.cm-live-media`；表格单元格也不是 `.cm-line` 的后代，因此被提前返回。
4. 根本原因是按部分预览组件的容器类推断所有组件的 DOM 结构。模型测试不能覆盖浏览器中的事件目标，真实桌面测试才暴露遗漏。

## 3. 解决方案

`src/renderer/editor/live-source-edit.ts:25` 将 `.cm-live-table` 加入捕获阶段的双击入口。表格依据现有 `data-source-from` 定位整个原始 Markdown 块，点击的单元格提供光标位置。通过现有 `editLiveBlock` 状态展开，Esc 或光标离开后收起。

捕获阶段覆盖了主动忽略 CodeMirror 普通事件的预览组件；只读、输入法组合输入以及按钮、语言输入框不触发源码展开。双击只更改选择和预览状态，不改文档文本。

## 4. 验证与影响范围

- 类型检查、构建通过；183 项单元测试通过。
- 35 项真实 Electron 回归通过，包括表格双击展开、Esc 收起、普通单击继续编辑单元格及保存原文。
- 新增回归同时覆盖标题、正文、列表、引用、任务列表、图片、公式、图表和代码块。
- 当前窗口正文从 800px 扩展到约 1452px，一级、二级标题没有文字下划线；切换布局前后逐字核对正文未变化。

## 5. 预防措施

- [x] 为每种预览容器执行实际双击，不能只验证共享状态字段。
- [x] 在源码展开前后核对完整原文，保留单击编辑和 Esc 收起的回归。
- 新增预览组件时，核对其根容器、源范围属性、事件忽略策略，以及共享源码入口是否能到达。

## 6. 经验总结

共享编辑动作必须验证每种组件的真实事件目标与容器结构。
