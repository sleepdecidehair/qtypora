# 故障复盘：资源错误被忽略导致不完整导出

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-30 |
| 发现环节 | 本地图片 HTML 导出及缺失图片联调 |
| 严重程度 | P1：可能生成缺少内容的导出文件并覆盖既有结果 |
| 影响范围 | 图片、公式、图表的 HTML/PDF 导出 |
| Issue / 提交 | 工作区未初始化 Git，未提交 |

## 根因与证据

预览与导出共用 `hydratePreview`。预览需要容忍单个块失败，但原实现将该容错行为也用于导出，
资源解析失败后仍返回 HTML，调用方无法区分完整导出与部分失败。
自定义 `qtypora-media` 协议最初没有完整启用 fetch/CORS 支持，图片可用于显示，却无法正常读取并内嵌。

## 解决方案

为导出启用 strict 选项：公式、图表和图片失败时向调用层传播错误，停止文件写入。
图片解析与内嵌完成后才请求原生保存目标。主进程使用临时文件和原子写入。
媒体协议启用标准、安全、fetch 和 CORS 支持，资源仍通过窗口所属的不透明令牌访问，
不向界面开放任意文件读取。HTML 内嵌本地图片的 data URI，以支持离线携带。
远程图片内嵌尚未实现时给出明确错误。

## 验证与预防

真实 Electron 用例：缺失图片导出显示错误，预先存在的输出文件内容保持不变。
成功导出的 HTML 包含本地 SVG 图片 data URI、MathML 和 Mermaid SVG，不保留媒体令牌地址。
PDF 输出具有 `%PDF-` 文件头并产生实际文件；文档脚本和事件属性被移除。

预览容错与交付产物完整性必须分别定义。导出成功必须意味着所有必要资源已处理完成，
不能只以“生成了一段 HTML”作为成功条件。
