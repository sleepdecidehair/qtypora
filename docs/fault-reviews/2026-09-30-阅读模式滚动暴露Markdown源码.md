## 问题描述

第一次滚动到表格等区域时，正文短暂出现 Markdown 写法，然后才转成预览。
图表渲染失败或尚未完成时也可能直接显示源码。最初按用户要求建立独立阅读视图；
用户随后要求调研并遵循 Typora 官方逻辑，最终公开模型恢复为实时预览编辑与全篇源码。

## 根因与证据

1. 原 `hybrid.ts` 实现服务于编辑：活动块显示原文，其他块由 CodeMirror 视口装饰转成预览。
   滚动、选择及装饰重算都参与这个过程，选择经过整个表格或图表会触发原文展示。
2. 表格结构虽可同步解析，但视口内创建预览块晚于原文进入布局，存在源码先被绘制的时间窗口。
3. `hydratePreview` 使用异步公式和 Mermaid 模块。原实现直接把源文本放在预览 DOM 中，
   渲染完成前或错误回退时仍能显示源文本。
4. Mermaid 解析错误消息本身包含输入上下文；仅把“原文”改成“错误信息”仍可能暴露源码。

## 解决方案

- 默认 `hybrid` 直接编辑，Ctrl+/ 双向切换 `source`；Ctrl+E 选择样式内容或表格单元格。
- 普通段落和标题使用原生 CodeMirror 行及行内装饰，不以整段组件替换可编辑正文。
- 表格保持渲染组件，单元格局部输入通过精确的源文范围事务修改，表格选择和滚动不展开整块。
- 公式和图表保留独立的显式编辑状态，滚轮及普通选区不会激活源码。
  原文在节点附着前保存在 JS Map 并清空 DOM，加载和失败仅显示通用中文提示。
- 模式切换以当前可见行或组件内的源行映射衔接位置；光标和历史单独保存，抑制打字机模式的光标居中干扰。
- 200,000 字符以上的实时预览目前退回普通源码编辑，列为明确性能边界，不能计为全尺寸预览已完成。

## 验证与预防

此前独立阅读方案的回归结果属于历史证据，不用来证明当前实时预览交互正确。
当前回归覆盖渲染单元格输入与精确撤销、25 个表格滚动期间的附着 DOM 源文监测、
60 节文章双向切换的可见标题位置，以及光标和历史的独立保留。最终结果见《开发验证记录》。

后续组件必须分别定义“预览可见”和“显式编辑激活”。异步读取、解析完成和界面附着是
不同的状态；原文与第三方解析错误不能作为图表加载占位。默认交互以官方文档为基线。
