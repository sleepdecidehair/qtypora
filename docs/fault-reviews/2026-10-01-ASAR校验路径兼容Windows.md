# 故障复盘：ASAR 校验使用固定斜杠导致 Windows 查找失败

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-10-01 |
| 发现人 | Codex 真实打包检查 |
| 严重程度 | P2 一般 |
| 影响范围 | 新增产物校验脚本；首轮打包停止，未更新成功产物记录 |
| 关联 Issue / PR / 提交 | 本地目录没有 Git 仓库 |

## 1. 问题描述

首轮 `20261001-115149-925fd5b8` 的应用及安装程序图标、外置品牌资源通过检查，读取 ASAR 界面文件时报 `"out/renderer/index.html" was not found in this archive`。

预期是核对 ASAR 中的界面 SVG；实际脚本提前失败，没有发布暂存安装包。对应记录为该运行的 `logs/failure.json`。

## 2. 临时解决方案

保留暂存包作为真实诊断样本，不跳过校验、不手工标记通过。

## 3. 根本原因分析

1. `asar.listPackage` 实际列出 `\\out\\renderer\\index.html`，排除文件缺失。
2. `asar.extractFile(archive, path.join('out', 'renderer', 'index.html'))` 可读取真实内容。
3. 本地 `@electron/asar/lib/filesystem.js` 按 `path.sep` 拆分路径。原检查脚本固定使用 `/`，与 Windows 路径规则不一致。

直接原因位于 `scripts/package-checks.cjs` 的 ASAR 查找及根目录过滤：提取路径没有使用原生分隔符，过滤表达式也没有归一化列表路径。根本原因是只考虑了常见 Unix 风格的归档路径，语法检查和旧图标失败测试不能覆盖成功读取 ASAR 的分支。

## 4. 解决方案

提取文件使用 `path.join`；仅在进行目录规则检查时将列表中的反斜杠归一化为 `/`。读取同一个实际暂存包验证，无需改变应用或归档内容。

修复限定在校验工具，不改变安装包内容和应用文件访问逻辑。

## 5. 预防措施

- 在 Windows 构建机验证完整成功分支，避免仅检查单一失败分支。
- 区分第三方 API 的原生路径参数和用于匹配规则的规范化字符串。
- 将真实产物检查作为成功目录更新之前的必经步骤。

## 6. 经验总结

第三方归档工具也可能使用操作系统分隔符；路径构造与规则匹配必须分别遵循其实际契约。
