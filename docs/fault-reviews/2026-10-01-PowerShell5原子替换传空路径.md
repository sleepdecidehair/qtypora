# 故障复盘：PowerShell 5.1 调用 File.Replace 时空备份路径失败

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-10-01 |
| 发现人 | Codex 后续打包分支专项验证 |
| 严重程度 | P2 一般 |
| 影响范围 | 已有 latest.json 时的记录更新；首次生成分支不受影响 |
| 关联 Issue / PR / 提交 | 本地目录没有 Git 仓库 |

## 1. 问题描述

在真实 Windows PowerShell 5.1 的隔离归档探针中，首次 `File.Move` 创建最新记录成功，后续 `[IO.File]::Replace(temp, latest, $null)` 报 `The path is not of a legal form`。此前完整打包创建首份记录时走的是首次分支。

## 2. 临时解决方案

保留完整构建产物；安装包内容和编译后的程序不受该记录更新问题影响，不重复编译应用。

## 3. 根本原因分析

对比同一探针的两种调用：传 `$null` 失败，传真实备份文件路径成功，并能读回更新后的记录和备份。PowerShell 5.1 对字符串参数的转换使空值不能按预期作为该 .NET API 的空路径参数处理。

直接原因位于 `scripts/package-internal.ps1` 的已有最新记录更新分支。设计只考虑了 .NET 方法签名，遗漏 PowerShell 调用边界；首轮创建没有执行该分支，所以需要重复发布的专项验证。

## 4. 解决方案

备份路径明确为本次成功构建的 `logs/previous-latest.json`，与最新记录位于同一磁盘。更新时保留原记录，同时原子替换新记录。该调整仅影响归档记录，不改变安装程序和应用资源。

除隔离探针外，用真实 `release/latest.json` 的相同字节执行了一次原子替换；替换前后摘要相同，备份摘要一致，结果写入成功产物的 `logs/latest-replacement-smoke.json`。

## 5. 预防措施

- 同时验证首次生成和已有记录的替换分支。
- 在实际 PowerShell 5.1 宿主中验证 .NET 参数转换，不只依据 API 签名。
- 保存备份记录，并在失败时保留可复核的原产物。

## 6. 经验总结

从 PowerShell 调用 .NET 文件 API 时，必须验证空值转换及已有文件分支。
