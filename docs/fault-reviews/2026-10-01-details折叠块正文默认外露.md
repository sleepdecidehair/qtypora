# 故障复盘：details 折叠块正文默认外露

## 基本信息

| 字段 | 内容 |
|------|------|
| 日期 | 2026-10-01 |
| 发现人 | 用户 ONB 分组反馈，Codex 原文与界面核验 |
| 严重程度 | P2，折叠功能失效 |
| 影响范围 | 实时预览中的多段 HTML details 折叠块 |
| 关联 Issue/PR/提交 | 无；当前目录不是 Git 仓库 |

## 1. 问题描述

用户文档用 `<details>` 和 `<summary>` 包裹 ONB-01 至 ONB-12 的测试用例，期望默认只显示分组标题，点击后展开正文，实际正文直接显示。

检查当时窗口中的 62,409 字符原文，存在正确配对的标签，第一组从第 303 行开始、第 495 行结束。视口中的 ONB-11 `<details>` 为关闭状态，但只包含一个 `<summary>` 子元素，正文位于折叠元素外部。因此不是用户添加了 `open` 属性，也不是点击状态错误。

## 2. 根因分析

1. Markdown 解析器遇到 `<details>` 开头后，在空行处结束一个 `html_block` token；随后标题、段落、列表、表格以及最终的 `</details>` 分别成为其他 token。
2. `src/renderer/editor/live-blocks.ts` 旧实现逐个 token 创建独立预览区块，没有将 HTML 容器的完整范围合并。
3. 每个区块分别净化和放入 DOM。浏览器自动补全第一个区块中的 `<details>` 结束标签，导致其只包住 summary，后续 Markdown 正文作为独立区块始终可见。
4. 根本原因是把 Markdown token 的范围直接当成独立 HTML 容器范围，没有处理跨 token 的容器结构。已有回归覆盖图片、表格、公式和代码，遗漏了 details 包裹多段 Markdown 的场景。
5. 修改前新增的 7 项边界测试中，4 项失败：完整正文被拆成 3 个区块，嵌套和相邻分组被拆成 6 个片段，代码示例、注释及属性中的标签文本也未得到完整范围验证。

## 3. 解决方案

- `src/renderer/editor/live-blocks.ts:18` 识别从 details 开头至匹配结束标签的 token 范围，按嵌套层级计数，完整渲染为一个预览区块。
- 只匹配 HTML token，跳过代码块和转义文字；注释和引号属性中的标签文本不会被误认为结束标签。
- `src/renderer/editor/live-blocks.ts:54` 将完整范围用于源码替换和编辑入口。未闭合标签保持原有分段显示，避免隐藏后文。
- `src/renderer/editor/live-blocks.ts:92` 在原生 toggle 事件后重新测量预览高度和资源尺寸。
- `src/renderer/editor/markdown.ts:123` 在净化白名单中保留无脚本能力的布尔 `open` 属性，其余事件属性仍被移除。无 open 时默认关闭，有 open 时默认展开，遵循 [HTML details 语义](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details#attributes)。
- `src/renderer/editor/editor.css:57` 增加折叠标题的鼠标指针及键盘焦点反馈。

无需修改用户的 ONB 内容或重写标签，修复位于编辑器渲染层。

## 4. 验证与影响范围

- 类型检查、构建通过；29 个测试文件中的 223 项单元测试通过。
- `src/renderer/editor/live-details.test.ts` 的 7 项边界测试全部通过，覆盖多段正文、表格、相邻和嵌套分组、代码中的关闭标签、注释、属性文字、单行 HTML、未闭合标签和转义文本。
- `tests/details-folding.spec.ts` 的 3 项 Electron 测试通过：十二组默认关闭，鼠标及空格键切换，原文和保存状态不变；嵌套独立折叠、显式 open、未闭合正文、HTML 导出；双击进入完整源码，编辑后恢复预览并准确保存。
- 共 6 项桌面回归通过，同时验证代码块创建、标题及普通内容的源码展开、图片和图表显示、表格编辑。

- 当前开发窗口的最新热更新模块已验证：示例得到一个包含正文和结束标签的完整区块。验证构造独立状态，没有派发编辑事务，前后用户文档内容相同。

## 5. 预防措施

- [x] HTML 容器回归同时检查容器边界和正文是否实际位于容器内。
- [x] 用真实 DOM 验证默认隐藏、点击展开及键盘操作，不只检查生成字符串。
- [x] 匹配容器时覆盖嵌套、代码、注释、属性引号和缺失结束标签。
- [x] 源码编辑与 HTML 导出验证采用相同内容样本。

## 6. 经验总结

Markdown 的 token 边界不一定是 HTML 容器边界。独立预览必须先识别完整容器，再进行净化、DOM 构造和源码范围映射。
