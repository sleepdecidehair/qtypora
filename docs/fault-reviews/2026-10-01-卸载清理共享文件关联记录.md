# 故障复盘：卸载清理不能删除共享的文件关联键

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-10-01 |
| 发现人 | Codex 隔离 NSIS 生命周期测试 |
| 严重程度 | P2 一般 |
| 影响范围 | 本次新增的文件关联卸载宏；尚未发布，真实 `.md` 未受影响 |
| 关联提交 | 本地目录没有 Git 仓库 |

## 1. 问题描述

在独立的私有扩展名中，先创建其他应用的默认类型与 `OpenWithProgids` 空字符串候选，再执行 QTypora 安装及卸载宏。预期其他应用的候选仍存在，实际读取返回空值，测试报 `Other application retained mismatch`。

## 2. 临时解决方案

停止发布候选包。测试使用随机应用名、私有扩展名与工作区目录，最终只清理本次测试的注册键，没有修改真实 `.md` 的默认选择。

## 3. 根因分析

相关位置是 `build/installer.nsh` 的 `customUnInstall`。删除自己的候选后，原实现继续用 `DeleteRegKey /ifempty` 删除共享 `OpenWithProgids` 和扩展名键。实际捆绑的 NSIS 3.0.4.1 未保留测试中的其他值；删除这两条命令后，相同集成测试通过。

根本原因是把共享键当作安装程序的私有资源，并依赖未在实际捆绑版本中验证的“空键”语义。单独检查注册成功无法发现问题；必须执行卸载并验证其他应用的记录仍在。

## 4. 解决方案

只执行 `DeleteRegValue` 移除 QTypora 自身的候选，保留共享扩展名键。私有应用和文档类型键仍根据打开命令归属清理：只有当前命令指向本次卸载目录时才删除，旧目录卸载不能删掉较新安装的注册。

验证入口是 `scripts/test-installer-icons.ps1`。测试实际编译并执行同一 NSIS 宏，覆盖图标注册与原生 Shell 渲染、重复安装、默认类型保持、未选择的快捷方式、旧目录卸载、其他候选保留和自身清理；五项检查通过。该检查已纳入统一打包脚本，记录在 `logs/installer-icons.json`。

## 5. 预防措施

- 对共享注册键只操作自己拥有的值，不整体删除父键。
- 在真实捆绑的工具版本中验证清理语义，不仅参考最新版文档。
- 卸载测试同时断言自身记录消失、其他记录与默认选择保持。

## 6. 经验总结

共享注册表位置必须按值归属清理，并以保留其他应用记录的集成测试验收。
