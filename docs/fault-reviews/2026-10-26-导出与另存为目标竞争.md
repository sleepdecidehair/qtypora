# 导出与另存为写入同一路径的竞争

日期：2026-10-26

## 触发与影响

窗口 A 将未命名文档另存为 `.md` 或 `.txt`，窗口 B 同时把 Markdown 或自定义程序结果导出到同一文件。A 的原子保存已写好临时文件、尚未替换目标时，文档记录仍没有新路径，因此 B 的“已打开源文档”检查无法识别这个正在保存的目标。

原实现中，保存按目标绝对路径排队，导出按带 `export:` 前缀的路径排队。两个队列互不等待，最终检查与替换可能交错，导致导出覆盖另一个窗口刚保存的内容。

## 修复

`src/main/exports.ts` 使用与 `saveMarkdown` 相同的规范化目标路径队列。导出仍在排队前记录目标版本，并在获得锁、完成临时写入后重新检查源文档路径和目标版本。竞争的保存完成后，导出返回 `CONFLICT`，不覆盖新内容，也不记为成功导出。

## 验证

新增 `src/main/exports-race.test.ts`，覆盖 Markdown `.md` 与自定义导出 `.txt` 两条可达路径。测试使用两个独立 `DocumentSession` 和真实临时文件，通过文件重命名屏障将另存为停在最终替换前；确认导出尚未进入目标写入，释放保存后断言导出失败、磁盘与文档内容保留、临时文件清理。测试不依赖固定等待时间。

- `npm run typecheck`：通过。
- `npm test -- src/main/exports-race.test.ts src/main/export-options.test.ts src/main/export-preset-files.test.ts`：3 个文件、12 条测试通过。
- 集成后编译成功；全部 412 项单元测试通过，完整桌面回归 120 项通过、1 项打包测试跳过。

此修复协调应用内目标写入。外部程序不参与本应用的路径队列，仍由写入前的文件版本检查检测外部变化。
