# 桌面测试宿主键盘干扰

日期：2026-10-26。结论：本次 Python 光标偏移和 HTML 高亮失败有明确的额外键盘输入证据，不应据此修改编辑器正常行为。

## 证据

对原有真实 Electron 用例临时记录键盘事件和 CodeMirror 事务：

- Python 语言提交后，`input.code-language` 与 `select.code` 正确将光标放在第 10 字符；随后出现测试脚本未发送的 `keydown: 1`，`input.type` 插入字符 `1`，光标成为 11。
- HTML 语言提交后原文围栏与光标正确；随后出现测试脚本未发送的多次 `keydown: Backspace`，第一笔 `delete.code-fence` 正常拆除围栏，于是 HTML 正文变为 HTML 预览，高亮数量变成 0。
- 同轮可见窗口的代码创建与引用切换未再失败；隐藏窗口后，原有代码围栏与引用切换 19 条用例全部通过，原文、保存、选区、光标和坐标断言未放宽。

诊断日志与临时诊断测试副本归档在仓库主目录的 `.task-artifacts/typora-parity/input-diagnostics/`。诊断监听与日志代码已从正式测试中移除。

## 测试隔离修改

`tests/desktop-helpers.ts` 默认隐藏自动化窗口并关闭后台节流；新建窗口也自动保持隐藏，避免抢占宿主焦点和接收宿主键盘输入。用例仍运行真实 Electron、Chromium、磁盘和 IPC。

重启并调整窗口尺寸的布局用例可稳定复现隐藏窗口截图超时：`capturePage` 的两种 `stayHidden` 设置、显式矩形加重绘，以及 CDP 截图均未解决；布局与源码断言此前已通过。这些观测不足以归因于单一参数。该路径仅对布局重启缩放截图显式启用 `presentInactive`：截图期间将窗口设为不可聚焦，以 `showInactive()` 提供实际画面；截图前后断言未获得键盘焦点，随后在 `finally` 隐藏窗口、恢复可聚焦属性及测试隐藏监听。普通截图使用全隐藏 `capturePage`，不切换原生窗口可聚焦状态。PNG 还需通过签名和非零尺寸检查，失败不会跳过截图。

后续全量回归发现，将临时显示应用到所有截图会改变正在编辑的输入框焦点。临时事件记录确认：语言输入为 `py` 后，截图期间发生 `blur`，正常的语言提交处理器将源码从 `javascript` 改成 `py`，之后 Escape 已无法取消。恢复全隐藏截图后，新增截图前后源码与焦点断言通过；这不是产品的 Escape 缺陷。

同轮目录搜索失败与截图无关，该用例没有截图调用。偏好设置的“完成”会等待异步持久化再关闭弹窗，主题颜色会提前更新。将偏好 IPC 临时延迟 500 毫秒后，稳定观察到弹窗仍打开时 `fill` 返回但未触发输入事件，输入值仍为 `word`，结果保持 1。测试现等待偏好弹窗消失后输入新搜索词。所有延迟和事件诊断代码均已移除，原结果、高亮与源文件断言保留。

人工可视检查可设置 `QTYPORA_TEST_VISIBLE=1` 后运行原有桌面命令。可视模式仍显示窗口，因此运行时应避免向测试窗口输入额外内容。多窗口设置用例仅在可视模式断言原生焦点，其持久化、窗口联动及原文验证仍保留。
