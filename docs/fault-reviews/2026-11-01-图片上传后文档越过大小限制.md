# 故障复盘：图片上传结果可让文档越过 16 MB 限制

## 基本信息

2026-11-01；P1 保存契约风险；发现于多 Agent 代码审查；关联修复提交 `dd9ab38`。

## 问题与根因

插入图片时预算检查发生在上传前，但自定义上传器返回的最终 URL 长度不可预知；批量上传、整理和上下文替换也存在相同缺口。结果可能在编辑器中形成超过 16 MB、之后无法按既有契约保存的文档。根因是按占位符或输入路径估算，而没有对最终 ChangeSet 应用后的真实编码字节做最后门禁。

相关位置：`src/renderer/editor/clipboard-import.ts:324-410`、`editor-context.ts:196-226`、`image-upload.ts:87-101`。

## 解决方案

所有异步 URL 已确定后，先把 ChangeSet 应用到内存文档，再按原编码、BOM 与 LF/CRLF 计算最终序列化字节；只有 `fitsPasteBudget` 通过才 dispatch，失败保留原文、选区和撤销栈。

## 验证与预防

图片上传预算测试覆盖接近上限的长 URL 拒绝和上限内成功。任何异步生成内容的编辑操作都必须在最终产物处复验保存契约，预估只能用于提前拒绝，不能代替提交前校验。
