# 故障复盘：文章统计在渲染线程同步解析大文档

## 基本信息

2026-11-01；P1 交互卡顿风险；发现于多 Agent 代码审查；关联修复提交 `dd9ab38`。

## 问题与根因

文章统计直接在 React 渲染链同步解析完整 Markdown，全文和选区各执行一次；错误回退仍可能把同一解析压回主线程，无选区时还创建空闲 Worker。根因是把 CPU 密集解析当作普通派生状态，缺少调度、取消、后台隔离和失败状态设计。

相关位置：`src/renderer/components/WordStatistics.tsx:17-54`、`hooks/wordStatistics.ts:65-157`、`hooks/word-statistics.worker.ts`。

## 解决方案

统计请求先去抖并等待空闲时机，再交给模块 Worker。generation 丢弃过期结果，在途任务通过终止 Worker 取消；Worker 按需创建，空选区释放独立通道，失败只在 Worker 中重试一次，连续失败显示不可用占位，不回退到渲染线程同步解析。无 Worker 环境保留受调度的兼容实现。

## 验证与预防

单元测试覆盖合并、取消、过期结果、懒创建、成功后释放、限次失败和 dispose；真实 Electron 统计与重启用例通过，约 1 MiB 文档实测后台统计阶段主事件循环最大间隔约 5.7 ms。CPU 密集派生计算必须验证正常路径、取消路径和错误路径都不回到 UI 主线程。
