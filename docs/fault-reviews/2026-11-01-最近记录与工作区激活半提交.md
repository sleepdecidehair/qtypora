# 故障复盘：最近记录和工作区激活可能出现半提交

## 基本信息

2026-11-01；P1 状态一致性风险；发现于多 Agent 代码审查；关联修复提交 `dd9ab38`。

## 问题与根因

最近文件、最近目录和工作区激活先修改内存状态再异步写盘，并发请求或写盘失败时会出现内存与磁盘不一致；文档打开在 recent 持久化等待期间还可能把旧文件身份发布为已打开。根因是把多个状态写入当成彼此独立的赋值，没有明确“持久化成功才发布”的提交点，也缺少对等待期间文件身份变化的二次验证。

相关位置：`src/main/preferences.ts:126-142`、`src/main/documents.ts:182-235`、`src/main/index.ts:380`。

## 解决方案

最近记录写入按同一队列串行化，先构造候选快照并写盘，成功后才替换内存。工作区先持久化最近目录，再切换根目录和 watcher。文档打开在未发布状态下建立临时 watcher，等待持久化后稳定重读，并核对版本及 dev/ino，全部成功才发布授权根和记录；失败关闭临时资源。

## 验证与预防

`preferences.test.ts` 与 `documents.test.ts` 覆盖并发写、磁盘失败回滚、等待期间同字节原子替换以及工作区持久化失败。以后涉及“写盘 + 内存 + watcher/授权”的流程，应先定义唯一提交点并覆盖等待窗口内的外部变化。
