## 复现与根因

| 项目 | 修改前证据 | 修复 |
| --- | --- | --- |
| 扩展标记配对 | 真实键入 `~`、`^`、`==` 分别得到 `~~`、`^^`、`====`。 | 空选区不补结束符，已有选区仍可包裹，保留上下文和组合输入保护。 |
| 表格行移动 | 单元格内 Alt+↑ 未改变表格原文。 | 复用已有整行源事务，严格检查修饰键、表头、首末行和只读；保持焦点列与撤销。 |
| qmd | 旧编译程序不能打开 `report.qmd`，标题仍为未命名。 | 将扩展表移入 shared，主进程与渲染进程使用同一识别函数。不是 Quarto 执行器。 |
| 上传协议 | 新增两项单测在旧实现失败；真实上传流程因日志中额外网址而没有替换图片。 | 读取末尾 N 个结果行，继续检查数量、协议和凭据，保留事务版本保护。 |
| 脚注悬停 | 原程序只有点击跳转。首版新增实现真实悬停也未显示，运行时位置为 3，而脚注原文从 2 开始。 | 按原文范围匹配悬停位置，使用真实起点读取定义，显示净化后的内容并去除媒体和重复标识。滚动关闭预览，避免使用离开视口的引用节点。 |

脚注完整回归还发现 Escape 先被默认键盘映射处理，导致正文选区从 21…23 收起为 23。悬浮层关闭事件改为最高优先级。重新构建后，选区、滚动恢复、重复引用、编辑定义、文档切换、只读与安全用例全部通过。

## 测试观察修正

模式切换后的布局测量会异步恢复滚动。最初在其完成前记录 scrollTop，把 12→32 的正常布局恢复误算为悬停行为；增加两帧等待后再记录基准。悬浮层初次挂载先在视口外测量，坐标检查改为先等待它进入视口。安全用例先等待原脚注的两个媒体请求结束，再检查悬浮层未新增请求，没有放宽净化要求。

测试环境的剪贴板读取可能返回没有 MIME 类型的空项，而 `ClipboardItem` 不接受空内容。快照跳过没有格式的空项，保留其他格式与既有恢复逻辑。工作区搜索断言使用平台路径拼接，避免 Windows 反斜线导致假失败。

## 保留的失败与限制

`file-history.test.ts` 的 `moves and undoes a directory while preserving open buffers, orphan drafts and resource tokens` 在 Windows 报权限或占用错误。在基线 `7165be95` 的隔离工作区重跑同一用例也失败，该工作区没有本轮文件服务修改。首批结束时故障未解决，不能称单元套件全绿，也不能将该失败证明为所有 Windows 环境均不可移动目录。后续修复见下一节。

未运行全量单元/桌面套件、macOS、实体输入法、真实云上传、官方客户端全量等值和安装包验证。相关功能继续按清单的待验状态处理。

## 第二批根因与修复，2026-11-11 至 11-12

本节补充首批之后的修复，不将上面的失败记录改成通过。功能分点提交到本地，不包含发布或推送。

| 项目 | 实际复现与根因 | 修复范围 |
| --- | --- | --- |
| Windows 目录移动 | 旧构建的真实双窗口目录重命名停留在输入框；单测报权限错误。原生实验中，无 watcher 或只监听源目录根时移动成功，监听嵌套目录时 `Directory.Move` 返回 Win32 5；关闭 watcher 后原字节保留且移动成功。 | 在已有文档锁内暂停受影响监听，在成功或失败后恢复并补读。保留排他移动、撤销身份检查、脏稿及资源授权；不以普通 rename 覆盖式回退绕过错误。 |
| 旧监听结果 | 操作前开始的异步读取可在目录移走后返回，错误报告新路径文档已删除。 | 读取完成后同时检查路径及 watcher 身份。关闭或重启监听后旧结果失效。 |
| 草稿写失败与删除重试 | 首轮审查发现 `fileMissing` 加空版本不能区分“已发现删除”和“已送达通知”；写草稿失败后会误跳过重试。新增两个失败优先用例先失败。 | 使用明确的 changed/removed 通知状态；草稿持久化成功后才记删除已通知。重复通知去重不阻止草稿重试。 |
| 删除后迅速重建 | 真实 watcher 配合延迟草稿写入，先送 changed，再被旧 removed 覆盖；基线也有该竞态。同版本重建也能触发。两个新增用例先失败。 | 成功读文件后推进观察代次，含同版本去重；挂起删除写完后检查代次。后继读取失败或草稿失败不取消有效删除。4 个新增竞态用例通过。 |
| 打字机滚动 | 源码与实时预览都不能达到居中坐标。运行时所有模式和版本检查通过，但控制台报 `Calls to EditorView.update are not allowed while an update is in progress`。CodeMirror 捕获该异常，单看 `pageerror` 会漏检。 | 测量回调结束后通过微任务派发滚动，执行前再次检查文档、模式、偏好与版本。桌面用例同时捕获控制台错误。 |
| 表格输入与滚动 | 独立审查发现每次 keyup 的同位 `select.table` 会使输入请求失效。默认 widget 坐标为整张表，而非当前单元格光标。 | 只有真实选区或文档变化推进版本；表格提供按原文范围定位的 `coordsAt`，活跃位置读取独立 Range，不修改原生选区。用完整按键和 24 行长表验收，不以 `insertText` 或两行表替代。 |
| TOC 层级样式 | 两个新单测与旧构建桌面用例确认官方 `.md-toc-h6 { display:none }` 不生效。既缺类名，也被主题属性过滤。 | 增加官方层级类，只对目录项放行 `display:none`，不放开正文全局 display；检查真实 HTML 导出、导航、动态改级与撤销保存。 |

最近记录清除沿用偏好存储的原子写入，持久化后广播快照；取消和真实写盘失败均不清空数据。固定目录与文件采用不同候选类型，目录名字以 `.md` 结尾仍按目录打开，删除目录后的失败不会替换当前文档。Windows 短路径的测试断言使用 `realpath`，没有放宽业务路径比较。

测试准备也作了修正。虚拟化长表先通过大纲滚入视口再量单元格坐标，不能在块尚未渲染时断言不存在。截图等待布局帧后再捕获，避免将上一个原生合成帧误当当前状态。仅输入居中测试分别检查点击、拖选、导航、真实输入及撤销保存。

系统版本历史的已知 Windows 单测失败仍保留。`limits version previews to a verified document session and preserves the draft` 在未包含本轮监听修改的基线上也失败，当前环境报“当前文档没有可验证的磁盘文件”。这不是 macOS 系统版本已通过验收的证据。本批不为消除测试失败而放宽版本文件身份校验。
