# 工作区目录操作

文件树支持在当前工作区内重命名或移动文件夹，也可使用「撤销文件操作」恢复最近的移动、重命名或新建操作。文件夹可拖到目标目录，也可选中后通过移动对话框指定目标。新建目录只有仍为空、身份未变时才可撤销；包含隐藏文件也视为非空。撤销历史只保存在当前窗口会话中，应用退出后不会保留，系统回收站操作不在此历史中。

目录移动使用系统的无覆盖重命名操作，不会覆盖已有目标，也不支持跨文件系统移动。工作区根目录、符号链接本身、正在作为任一窗口工作区的目录及其祖先目录不能移动；不能将目录移入自身或其子目录。目录内部的符号链接作为目录内容保留，不会被遍历；相对链接移动后的解析结果可能变化，访问资源时仍需通过路径授权检查。

目标路径如仍被任一窗口的打开文档、工作区、恢复草稿或已加载资源引用，即使磁盘上该位置已不存在，也会拒绝移动、新建或撤销移动。对大小写或 Unicode 写法可能指向相同目标的情况，按占用处理；无法确认旧路径与源目录是否相同的情况也会拒绝，避免将编辑内容关联到错误文件。

已标记为移除的文档再次保存时会要求选择保存位置；取消后保留编辑内容和恢复草稿。如果原位置后来出现另一个字节相同的文件，也不会仅凭内容相同而自动覆盖它。

移动期间，应用会协调各窗口的文件打开、保存、导出和图片操作；已有相关操作或系统对话框等待完成时，目录操作会提示冲突。已打开文档的内容、草稿、监听路径和已授权的资源地址随目录更新；没有打开的恢复草稿也会更新路径。如果磁盘移动已完成但草稿持久化失败，应用报告实际状态，并要求保留窗口、另存文档。外部程序可能同时修改文件系统；应用会核对源目录身份、拒绝已替换的项目，发生无法安全恢复的冲突时提示检查新旧路径。

移入系统回收站前会再次检查文件身份及所有窗口的工作区，已打开文档的编辑内容保留。系统回收站接口无法按文件身份原子地执行：最后检查与系统调用之间，外部程序仍可能替换该路径；请通过系统回收站恢复被移动的项目。撤销新建目录使用系统的空目录删除，身份检查和删除之间也存在同类外部竞争，非空目录不会被删除。

macOS 使用系统 `renamex_np` 的 `RENAME_EXCL`；Windows 使用 .NET `Directory.Move`。本轮原生目录事务已在 macOS 验证，Windows 实机行为仍待验证；不支持的系统不会回退为可能覆盖目标的普通重命名。
